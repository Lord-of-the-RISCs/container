# SpecHLS development containers

This repository contains Docker configuration files for SpecHLS development. These containers can be used to setup a full development environment on any machine, that can be accessed through, e.g., [Visual Studio Code Dev Containers](https://code.visualstudio.com/docs/devcontainers/containers).

## Docker setup

### Linux

For Linux hosts, you can install Docker through your distribution's standard package manager.
```sh
# Arch Linux
sudo pacman -S docker
# Ubuntu
sudo apt install docker
# Fedora
sudo dnf install docker
```

Docker is managed through system services on most distributions, and can be started using
```sh
sudo systemctl start docker
```
Alternatively, you can enable Docker on system startup by issuing
```sh
sudo systemctl enable docker
# Start Docker for the current session (avoids reboot)
sudo systemctl start docker
```

### Mac OS

You can download Docker Desktop from [the official Docker website](https://docs.docker.com/get-started/get-docker/). Follow the installation instructions, and you should be ready to go!

## Building the image

The contents of the Docker image are described in the [`Dockerfile`](Dockerfile) configuration file. To build the corresponding image, run the following command inside the directory containing the `Dockerfile`.
```sh
docker build --tag 'spechls-dev' .
```
This operation may take a long time, since it will build LLVM, MLIR, and all of SpecHLS' required dependencies.

**WARNING:** The SpecHLS development image requires around 25 GiB of free disk space. Make sure you have enough space available before attempting to build the image.

## Running the container

Once the image has been built, you can run the container by using the following command.
```sh
docker run -it spechls-dev
```
You will enter an interactive shell, where you will have access to the SpecHLS source files.

**NOTE:** You will automatically be logged in as the `spechls-user` user. This user has administrative privileges, and its password is `spechls`.

## Connecting to the container using Visual Studio Code

Visual Studio Code allows direct connections to running Docker containers through its [Dev Containers](https://code.visualstudio.com/docs/devcontainers/containers) extension. To get started, install the extension from the Marketplace.

Once installed, open the command palette (`Ctrl+Shift+P`) and search for the `Dev Containers: Attach to Running Container` option. Select the SpecHLS container from the list. A new workspace will be opened, from which you can open the folder you want to work from.

### Recommended extensions

To improve your development experience, we suggest you install the following extensions:
- `clangd` from LLVM
- `C/C++` from Microsoft
- `CMake Tools` from Microsoft
- `MLIR` from LLVM
- `Python` from Microsoft
- `LLVM Tablegen` from Jakob Erzar

Once inside your Dev Container, go to the extensions tab and install the extensions inside the container.

When you open your first C++ file, you will be prompted to install the latest version of `clangd`, which will provide you with LSP functionality (go to definition, autocompletion, etc.). The latter conflicts with Intellisense, which is provided by Microsoft's C/C++ extension. When prompted, disable Intellisense to use `clangd` as your LSP.

**NOTE:** `clangd` uses a compilation database (`compile_commands.json`) to lookup include files, compiler flags, etc. This file is automatically generated by CMake when configured through Visual Studio Code's interface. If working on the command line, you can pass `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON` to your CMake setup command to generate the compilation database.

## Troubleshooting

### Docker command failed to execute

The following error message indicates that the Docker background services are not running.
```
Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Is the docker daemon running?
```
You can start the daemon using `systemctl` as follows:
```sh
sudo systemctl start docker
```

### Some extensions do not show up in the VSCode Marketplace

Make sure you are using the Microsoft-provided version of VSCode. Open-source implementations such as VSCodium replace the official Marketplace with an alternative version that doesn't include all available extensions.
